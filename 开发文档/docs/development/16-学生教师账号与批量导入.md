# 学生教师账号与批量导入

日期：2026-10-13。范围：教师角色、学号/工号登录约定、系统管理员批量开户接口，以及 Web 权限修正。不扩展预约、审批或候补业务。

## 账号与权限

- 学生角色为 `STUDENT`，教师角色为 `TEACHER`。学生账号名填写学号，教师账号名填写工号；两者沿用 `user.username`，不另复制一份编号，也不自动添加前缀。
- 编号按字符串处理，保留前导零及大小写。当前格式为 3–64 位字母、数字、下划线、点或短横线；拿到实际数据集后再核对来源格式，不推测固定长度。
- 学号和工号共用用户名唯一约束。同号人员不能静默合并、改名或覆盖密码，需先核对数据。现有管理员和既有账号不批量改名。
- 教师与学生目前均可登录、查看开放目录及查询可用组合。申请、取消等功能仍待后续预约阶段实现。
- 教师默认没有资源管理和审批权限。需要管理时，系统管理员另外授予 `RESOURCE_ADMIN`，并配置审批组或资源管理范围；整笔审批仍要求审批组授权。
- `TEACHER` 通过新增 Flyway `V2__teacher_role.sql` 加入，不修改已执行的 V1。角色变化继续递增身份版本、撤销旧会话。
- Web 菜单和管理员选择器改为明确检查 `RESOURCE_ADMIN` / `SYSTEM_ADMIN`，不再把所有非学生用户视为管理员。

## 已实现接口

基础路径为 `/api/v1`，两个接口都需要系统管理员登录。批量入口与文件格式解耦，目前接受 JSON，不接受文件上传；后续 Excel/CSV 解析可转换为相同的 `rows` 结构。

| 方法与路径 | 行为 |
| --- | --- |
| `POST /users/imports/preview` | 校验输入，格式全部合法后查询已有账号；不写账号、批次或密码，不要求幂等键 |
| `POST /users/imports` | 带 `Idempotency-Key` 重新校验并整批创建，成功返回 201 |

两个接口请求体相同。下面编号、姓名和密码均为契约示例占位内容，不是已创建账号：

```json
{
  "rows": [
    {
      "number": "0020260001",
      "displayName": "示例学生",
      "roleCode": "STUDENT",
      "initialPassword": "<student-initial-password>"
    },
    {
      "number": "00010001",
      "displayName": "示例教师",
      "roleCode": "TEACHER",
      "initialPassword": "<teacher-initial-password>"
    }
  ]
}
```

每批 1–50 人。`number` 直接作为登录名；批量接口没有自定义 username 覆盖项。姓名最多 100 个字符；初始密码逐人提供，长度 12–72 个字符且不超过 72 个 UTF-8 字节，不自动以学号/工号或固定公共密码初始化。编号、姓名会去除两端空白，密码不做 trim。

批量入口只允许一个 `STUDENT` 或 `TEACHER` 角色，不接受管理员角色。需要管理权时开户后走既有角色和审批组接口。

预览 data 包含：

- `total`：提交的人员行数。
- `canImport`：本次预览是否通过。预览不预占账号，确认前账号仍可能被其他管理员创建。
- `items`：格式全部通过后返回行号、username、displayName、roles，不返回密码。
- `errors`：从 1 开始的 row、field、code、message。格式错误先修正后再次预览；确认仍独立验证，不信任客户端预览状态。

确认 data 为 `created` 和 `items`（创建的账号摘要）。成功后，相同操作者、幂等键及规范化内容重试回放原响应，响应头 `Idempotency-Replayed: true`。名单顺序属于请求内容；修改名单或初始密码必须使用新键。网络结果未知时保持原键，避免重复提交。

| 情况 | 结果 |
| --- | --- |
| 批次为空或超过 50 人 | 400 `VALIDATION_ERROR` |
| 批内重号、非法编号/姓名/角色/密码 | 预览返回行错误；确认返回 422 `IMPORT_HAS_ERRORS` |
| 与已有账号同名，包括学号与工号冲突 | 预览行错误 `USERNAME_EXISTS`；确认返回 409，整批不写入 |
| 同一键但名单或密码不同 | 409 `IDEMPOTENCY_KEY_REUSED` |
| 普通学生、教师、资源管理员调用 | 403 |

## 一致性和凭据处理

确认操作复用账号管理的幂等事务和管理员守卫锁。在锁内重新检查操作者身份与会话、全部账号名，再写入账号、角色、审计和成功响应。并发导入相同账号时仅一批成功；任何数据库异常均回滚本次整批事务。已存在账号不会被覆盖、重置密码或追加角色。

BCrypt 在事务外计算，数据库只存 BCrypt 摘要；幂等请求指纹采用现有密码 HMAC 机制。接口响应、审计和验收报告不含初始密码。调用方负责安全分发逐人初始密码；本轮未新增密码重置或首次登录强制改密功能。

Hutool 使用现有 `5.8.47` 依赖中的 `StrUtil.trim/isBlank` 和 `ReUtil.isMatch`，处理名单字符串和格式。密码编码继续使用 Spring Security BCrypt，JSON 继续使用现有 Jackson。未来可评估 Hutool Excel 工具，但真实表头、编号单元格类型与数据格式需在收到数据集后确定，本轮未增加 Excel 上传 UI 或文件解析器。

cd web-admin
npm run build
cd ..
XMUT_WEB_TEST=1 python3 deployment/scripts/personnel-smoke.py
