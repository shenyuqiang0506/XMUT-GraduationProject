## 工程决策

保留 `GraduationProject/` 原始目录，避免把依赖准备扩大为完整服务拆分。当前业务工程为后续服务提供依赖基础，Gateway 单独使用 WebFlux，业务工程使用 MVC/JDBC。根 POM 聚合两个模块，后续继续按工程约定拆分 identity、booking、ai、notification。

Spring Security 依赖提供 JWT/JWK 和 BCrypt 能力，不额外引入另一套 JWT 库。调度使用 Spring 自带能力，不引入 Quartz。JSON 使用 Boot 管理的 Jackson。没有安装前端、uni-app、JMeter 或部署服务，这些需要对应工程与使用阶段。

Nacos 与 AI 由独立 Spring profile 启用。生产默认配置不禁用数据库或 Flyway；仅测试 profile 使用 H2 并关闭 Flyway。示例只包含环境变量和占位值，默认不开放 Swagger UI。尚未实现生产认证或权限规则。

首次依赖下载发现 Flyway 的传递 POM 引入 GitHub Packages 仓库，其 metadata 返回 401。新增 `.mvn/settings.xml` 将仓库映射到 Maven Central，确保当前全部正式版依赖可从公开源解析。

## Lombok 与 Hutool 补充（2026-10-11）

按用户要求，根 POM 为七个 Java 模块统一引入 `org.projectlombok:lombok:1.18.46` 和 `cn.hutool:hutool-all:5.8.47`。Lombok 版本沿用 Boot 4.0.8 的管理值，使用 provided/optional，并显式配置编译注解处理器；四个 Spring Boot 应用运行包排除 Lombok。Hutool 使用 compile 范围，完整工具包进入运行包，现有 Jackson、POI、JWT、密码、事务等业务实现保持原样。

执行 `clean verify dependency:tree -Dincludes=org.projectlombok:lombok,cn.hutool:hutool-all` 后，七模块构建通过，基础测试共 6 项通过。新增依赖冒烟测试实际调用 Lombok 生成的构造器/getter 及 Hutool `StrUtil`；依赖树确认全部模块解析到统一版本，四个可执行 JAR 均包含 Hutool 且不含 Lombok。IDEA 重新加载 Maven 后可检索两个库的类。OSV 对上述两个坐标及版本的查询未返回已知漏洞记录；该结果不是整个依赖树的安全认证。

证据：[工具依赖验证摘要](../verification/2026-10-11/utility-dependencies.json)。配置依据：[Lombok Maven 接入](https://projectlombok.org/setup/maven)、[Hutool 安装说明](https://doc.hutool.cn/pages/index/)。本节记录后续补充，前文首次验证记录保持当时范围。

## Lombok 构造器改造（2026-10-11）

将身份、资源目录、网关与 M1 调用链中的 13 个纯赋值构造器改为 `@RequiredArgsConstructor`。生成构造器按未初始化的 final 字段声明顺序接收依赖；调整 `UserAdministration` 和 `UsersController` 的字段排列以保持原参数顺序。6 个原包内构造器显式使用 `AccessLevel.PACKAGE`。用编译前后 `javap -p -s` 输出核对，13 个构造器签名与访问权限全部一致。

含 `@Value` 配置参数、TTL 校验、密钥读取、HTTP 客户端和导入存储初始化、POI 安全限制的构造器保留显式实现，现有 record 不变。没有引入字段注入、统一 `@Data` 或 Hutool 业务替换。
