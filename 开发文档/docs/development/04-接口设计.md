# 接口设计

本文是完整 API 契约。M2 身份、目录、审批组与目录导入接口已实现，M3 来源覆盖、开放占用维护、策略和可用组合查询已实现；申请 / 审批等其余接口按里程碑推进，见 [M3 实现范围](14-M3可用性基础验收.md)。基础路径 `/api/v1`，所有 ID 为字符串，时间采用带偏移 ISO 8601。普通接口返回 code、message、data、traceId。下文省略重复的外层响应结构。

实际写入操作携带 `Idempotency-Key`（人员预览只读，不要求），状态操作同时带 expectedVersion。身份由 JWT 确定，客户端不得通过 applicantId/operatorId 指定他人身份。

权限：S 学生，T 教师，R 资源管理员，A 系统管理员，L 任意已登录用户；标记角色后还必须检查对象和管理范围。

## 2. 可用组合查询

请求示例（用于契约说明）：

```json
{
  "campus": "示例校区",
  "startAt": "2027-03-10T14:00:00+08:00",
  "endAt": "2027-03-10T16:00:00+08:00",
  "participantCount": 60,
  "requiredFeatures": ["PROJECTOR"],
  "equipmentRequirements": [{"type":"MICROPHONE","count":2}],
  "preferredBuilding": null,
  "dataMode": "DEMO",
  "page": 1,
  "size": 20
}
```

查询只返回同一审批组的组合；按时间、权限、完整覆盖、容量与设备数量校验。返回结果有生成时间，不是占用承诺：

```json
{
  "items": [{
    "venueId": "1001",
    "venueName": "示例活动室",
    "equipmentIds": ["2001","2002"],
    "resourceIds": ["1001","2001","2002"],
    "approvalGroupId": "10",
    "availability": "AVAILABLE",
    "coverageStatus": "COMPLETE",
    "dataMode": "DEMO",
    "checkedAt": "2027-03-01T10:00:00+08:00",
    "policyVersion": 1
  }],
  "page": 1,
  "size": 20,
  "total": 1
}
```

查询不暴露别人申请人的姓名、活动说明或完整审批备注。dataMode 受环境与角色约束，不能由请求强行把 REAL 资源变成 DEMO。

已实现的策略范围仅为 REAL / DEMO；当前没有已确认生效策略时，查询返回空 items、total=0 和 `unavailableReason=POLICY_NOT_CONFIGURED`。日历另返回 `coverageIntervals`（from / to / coverageStatus / checkedAt）和 `openingRules`，外部占用只暴露 startAt / endAt / type=EXTERNAL。

来源导入新增 EXTERNAL_OCCUPANCY / CONFIRMED_FREE_INTERVALS；完整声明的 queryContext、文件字段及维护 DTO 见 [M3 验收约定](14-M3可用性基础验收.md)。覆盖范围最多 31 天，组合查询限上海同一自然日。额外错误：SOURCE_SNAPSHOT_STALE / IMPORT_RANGE_CONFLICT / SOURCE_KEY_EXISTS 为 409；QUERY_TOO_BROAD 为 422，需要缩小查询范围。

## 3. 创建申请（待后续实现）

```json
{
  "activityName": "示例课程项目交流",
  "description": "接口说明用例",
  "participantCount": 60,
  "startAt": "2027-03-10T14:00:00+08:00",
  "endAt": "2027-03-10T16:00:00+08:00",
  "venueId": "1001",
  "equipmentIds": ["2001","2002"]
}
```

从登录用户确定 applicantId；从资源确定审批组与数据模式，从服务器确定规则版本。校验资源唯一性、单一场地、单件设备、当前借用权限、容量、覆盖、开放时间、申请额度与时间冲突。

成功 HTTP 201，data：applicationId、status=PENDING_APPROVAL、version=0、holdExpiresAt、startAt、endAt、resourceIds、policyVersion、dataMode。幂等重放返回保存的原状态码和结果，可用响应头 `Idempotency-Replayed: true` 标识。条件冲突返回 409，不能先成功占用场地再报告设备失败。

申请详情返回当前状态、version、占用有效期、资源快照、本人可见的审批记录和 allowedActions。allowedActions 帮助界面展示，真正操作仍校验。

## 4. 状态动作

approve/reject/cancel/resolve-conflict 均接受 reason、expectedVersion。拒绝与冲突处置要求 reason。审批组首个合法管理员动作生效，其他动作收到 VERSION_CONFLICT 或 INVALID_STATE。客户端重新拉取详情，不自动重复审批。

取消和审批成功 data 返回 applicationId、status、version、releasedResourceIds（需要释放时）、updatedAt。管理员在已开始活动上的特殊处置必须有明确业务规则；第一版不开放学生超期取消。

## 5. 候补

创建请求沿用创建申请字段，返回 waitlistId、status=WAITING、groupId、queuePosition、version。组合全空闲时返回 WAITLIST_NOT_NEEDED，提示走普通申请。

OFFERED 响应展示 offerExpiresAt；confirm 在同一事务中生成 application、转移全部暂占 owner、更新候补状态，返回 waitlistId、applicationId、applicationStatus、version。确认成功不等于审批通过。

同一用户同组已有 WAITING/OFFERED 时返回 DUPLICATE_WAITLIST。位置仅表示同一固定资源组合与区间的组内顺序；不显示“全校排队第几名”。

## 6. 导入与外部占用

preview 类型：RESOURCE_CATALOG / EXTERNAL_OCCUPANCY / CONFIRMED_FREE_INTERVALS。queryContext 至少说明来源、筛选日期节次、覆盖范围是否完整及采集时间；缺失时只导入目录或标为 PARTIAL，不能声明 COMPLETE。

preview 返回 batchId、fileHash、status、summary（sourceRows/newRows/updateRows/errorRows）、fieldMapping、errors、requiresConfirmation。存在阻断错误不能 commit。确认以批次内保存的文件及映射为准，禁止确认时换文件。文件在服务端生成存储键，保存到受控导入卷或对象存储；客户端不提交服务器文件路径。

commit 返回 COMMITTED 批次及受影响申请的冲突数量。新外部占用与已批准申请冲突时标为 CONFLICT_REVIEW；不能为保持“预约成功”而忽略学校真实占用。

更新资源、开放规则和占用均进行当前管理范围验证。规则改变影响已有申请时记录受影响项并交管理员处理。

## 7. AI 消息

```json
{"text":"周五下午六个人讨论项目，需要投影，使用两小时","clientMessageId":"示例唯一消息ID","expectedConditionVersion":0}
```

data 包含 messageId、conditionVersion、status、reply、conditions、missingFields、plans、checkedAt。status 为 NEED_CLARIFICATION / READY / NO_MATCH / FAILED。READY 只是可查询方案已生成，不是预约成功；前端确认后调用普通 `/applications`。

消息可以同步返回首版结果，接口超时上限明确；后续若改成异步或流式，需版本化增加消息状态查询或 SSE 契约。clientMessageId 用于重复消息去重。

## 8. 错误码

| 业务码 | HTTP | 客户端行为 |
| --- | --- | --- |
| VALIDATION_ERROR / TIME_RANGE_INVALID | 400 | 标记字段与原因 |
| UNAUTHORIZED / SESSION_REVOKED | 401 | 串行刷新一次或重新登录 |
| FORBIDDEN | 403 | 显示权限不足 |
| NOT_FOUND | 404 | 返回列表或重新查询 |
| RESOURCE_CONFLICT | 409 | 展示有权限可见的冲突资源，重新查询 |
| VERSION_CONFLICT | 409 | 拉取最新状态，用户重新决定 |
| IDEMPOTENCY_KEY_REUSED | 409 | 原键对应不同请求，停止自动重试 |
| REQUEST_IN_PROGRESS | 409 | 复用原键短暂退避或查询本人记录 |
| INVALID_STATE | 409 | 更新详情，隐藏已不可用动作 |
| WAITLIST_PRIORITY | 409 | 同组已有候补，应按候补规则申请 |
| WAITLIST_NOT_NEEDED / DUPLICATE_WAITLIST | 409 | 转普通申请或显示已有候补 |
| OFFER_EXPIRED / APPROVAL_HOLD_EXPIRED | 409 | 显示到期并重新查询 |
| RESOURCE_CLOSED / APPROVAL_GROUP_MISMATCH | 422 | 修改资源组合 |
| COVERAGE_UNKNOWN / SOURCE_NOT_BORROWABLE | 422 | 提示核实，不自动推断空闲 |
| APPLICATION_LIMIT_REACHED | 422 | 提示查看已有申请 |
| IMPORT_HAS_ERRORS | 422 | 修复文件并重新预览 |
| RATE_LIMITED | 429 | 按 Retry-After 等待 |
| AI_UNAVAILABLE / SERVICE_UNAVAILABLE | 503 | 提供普通筛选或稍后再试 |

错误响应 data 可有 fieldErrors、resourceIds、currentVersion、currentStatus，不返回数据库异常栈与他人信息。

## 9. 内部接口与事件

AI 通过内部只读接口查询资源，接口字段与公开查询共享校验；内部路径不直接暴露公网。身份传递使用受校验的用户 JWT 和调用服务身份，不能仅信任客户端提交的 X-User-Id。

预约事件格式：

```json
{
  "eventId": "示例UUID",
  "eventType": "APPLICATION_APPROVED",
  "aggregateType": "APPLICATION",
  "aggregateId": "3001",
  "aggregateVersion": 1,
  "occurredAt": "2027-03-01T10:05:00+08:00",
  "recipientIds": ["501"],
  "payload": {"status":"APPROVED","reason":null},
  "traceId": "示例请求标识"
}
```

事件类型包括申请提交/批准/拒绝/取消/过期/完成/外部冲突，以及候补通知/过期/取消。事件载荷不携带刷新令牌或模型凭据。事件用于通知和候补触发，预约状态以预约库为准。

第一版 `/admin/audit-logs` 查询预约库业务审计；账号与角色变更在身份服务留存，未来如需统一后台展示，应新增身份审计查询契约，不能直接跨库查询。

## 学生与教师开户补充

`POST /users` 的学生 username 填学号，教师填工号，roleCodes 支持 TEACHER；教师获得管理权限需另行授权。批量开户仅允许 STUDENT/TEACHER，详见 [请求、错误与验证](16-学生教师账号与批量导入.md)。
