## 2. 覆盖与导入约定

目录中 `sourceSystem` 必须与导入来源一致；`sourceId` 是来源资源编号，须按字符串传递以保留前导零。`dataMode` 必须与资源相同。DEMO 仅允许 dev/test 使用，不与 REAL 共享证明或策略。

完整占用快照的 `queryContext` 示例（仅用于说明，实际导入必须使用本次核实时间）：

```json
{
  "from": "2027-03-10T08:00:00+08:00",
  "to": "2027-03-10T18:00:00+08:00",
  "capturedAt": "2027-03-09T10:00:00+08:00",
  "completeness": "COMPLETE",
  "sourceDescription": "DEMO 示例：已核实所选资源及整个查询窗口",
  "resourceIds": ["1001", "2001"]
}
```

COMPLETE 必须显式指定 1–100 个不重复的资源 ID、完整窗口、非未来采集时间和非空来源依据；时间携带偏移，精度不超过毫秒，单次范围最多 31 天。只有在真实来源确实确认完整时才能选择 COMPLETE。

占用文件行包含 `sourceId`、`sourceKey`、`startAt`、`endAt`、`reasonCode`；原因限定 COURSE / EXAM / MAINTENANCE / OTHER。`__fragment_` 为系统保留编号前缀。完整占用快照允许文件为 `[]`，表示**显式资源窗口内已确认无该来源占用**，并不是全校资源空闲。

PARTIAL 缺少范围时可由有效行推导，缺少采集时间时使用服务端当前时间，但始终不能证明空闲；缺失的占用不会自动删除。较新 PARTIAL 替换窗口内旧覆盖后，该窗口不再沿用旧 COMPLETE 结论。

已确认空闲文件包含 `sourceId`、`startAt`、`endAt`，不能为空。只为实际行建立覆盖；相接区间可合并证明查询窗口，中间缺口仍 UNKNOWN。COMPLETE 空闲行只消除该来源在该行区间内的旧占用，其他来源占用仍会阻止组合。

完整替换仅清理确认窗口内记录，跨窗口占用与覆盖会拆分保留左右部分。部分导入不能移动窗口外记录，完整导入也不能借编号复用移走完全处于窗口外的占用。迟于已保存来源历史的旧采集快照返回 SOURCE_SNAPSHOT_STALE；此检查按资源与来源进行，当前采用保守策略，即不因窗口不同而接受旧快照。

预览和确认都检查当前权限。确认使用服务端保存的文件和 SHA-256，文件变化或阻断行错误会拒绝整批提交。多资源事务按资源 ID 升序锁定，批次、占用、覆盖和审计一起成功或回滚。手工登记占用不创建完整覆盖。

## 3. 查询与管理接口

基础路径 `/api/v1`。以下接口均已实现：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/resources/{id}/calendar?from=…&to=…` | 已授权资源的日历；最多 31 天 |
| POST | `/availability/search` | 已登录用户查询可行组合 |
| PUT | `/admin/resources/{id}/opening-rules` | `expectedVersion` 与 `rules`；只允许当前管理范围 |
| GET / POST | `/admin/resources/{id}/external-occupancies` | 分页查看 / 登记占用 |
| PATCH | `/admin/external-occupancies/{id}` | `expectedVersion`、`active`、起止时间与原因 |
| GET | `/admin/policies/{scope}` | 管理员查看 REAL / DEMO 当前规则 |
| POST | `/admin/policies/{scope}/versions` | 系统管理员创建并启用新版本，提交当前版本及依据 |
| POST | `/admin/imports/preview` | 在原目录导入接口增加 EXTERNAL_OCCUPANCY / CONFIRMED_FREE_INTERVALS |
| POST | `/admin/imports/{id}/commit` | 确认已预览批次 |

写接口需要 `Idempotency-Key`；不同内容复用同一个键返回冲突。规则和占用维护使用乐观版本及资源行锁，策略使用固定范围行锁和数据库唯一约束保证单个生效版本。

时段使用半开区间 `[startAt,endAt)`，前一个活动结束与下一个开始相接不冲突。组合查询限制在同一个上海自然日，结束恰好跨至次日零点也不接受；日历允许跨日。查询同时检查策略的提前量、最远天数和最长时长。未配置策略时返回空列表及 `unavailableReason=POLICY_NOT_CONFIGURED`，不会套用演示默认值。

可行组合要求每个成员覆盖有效且完整、没有已知外部占用、在开放时间内、审批组有效；REAL 场地来源必须明确可借，设备状态必须 GOOD。必需特征标为 UNKNOWN / 未知 / 待核实或明确否定时不满足要求。设备类型不能重复，单次最多需求 40 件设备。每处场地返回一套按设备 ID 确定的可行组合，分页 total 统计符合条件的场地数；候选超出当前计算上限时返回 QUERY_TOO_BROAD，提示缩小范围，不截断后虚报完整结果。

查询使用 MySQL 一致性快照，结果携带 `checkedAt` 和 `policyVersion`。**查询不会暂占资源**，后续申请必须再次按资源锁协议校验。目录列表的 UNKNOWN 仍不能用作预约判据。

## 4. 数据库与恢复

新增 Flyway V2 建立 `booking_policy_scope`、`booking_policy`、`availability_coverage`、`external_occupancy`。范围守卫只预置 REAL / DEMO 标识，不预置制度参数；生效范围生成列的唯一索引防止双生效版本。所有引用带外键，区间、枚举及版本带 CHECK，资源 / 活跃状态 / 区间与批次建立索引。

覆盖保留 inactive 历史；外部占用保存 `observed_at`、`version`，手工占用没有导入批次，故 `import_batch_id` 可空。导入产生的记录仍绑定批次，拆分片段保留原采集时间与来源批次。

迁移前已将 dev 预约库备份到私密目录 `deployment/secrets/dev/backups/booking-before-m3-availability.sql`，权限为 600，未纳入 Git。V1、V2 均已在本机 dev 执行，必须保持原始内容，包括排版；后续修改新增 V3。若需恢复，应先停止本机写入并额外保存当前数据，在独立恢复库检查私密备份与 Flyway 记录，再切换连接；不能直接删除业务表当作回滚。此次未执行灾备恢复演练。
