# Web 与 App 设计

## 1. 页面职责

Web 管理端用于批量维护、审批和统计；iOS/Android 学生端用于查询、申请、候补、消息与 AI。用户账号、业务状态和数据范围来自同一后端，页面不维护独立预约数据库。

## 2. Web 页面

| 页面 | 内容和主要操作 | 对应接口 |
| --- | --- | --- |
| 登录与个人资料 | 登录、退出、当前角色 | auth、users/me |
| 管理概览 | 待审批、冲突、到期、通知失败数量 | admin/applications、statistics |
| 资源目录 | 分页筛选、新建、编辑、开放/停用、版本冲突提示 | resources、admin/resources |
| 资源详情与日历 | 属性、设备、开放、外部占用、覆盖未知 | calendar、opening-rules、external-occupancies |
| 导入向导 | 上传→字段映射→校验预览→确认→结果 | imports/preview、imports/{id}、commit |
| 审批列表与详情 | 查看整组资源和来源核查、批准/拒绝 | admin/applications、approve/reject |
| 外部冲突处理 | 展示原因和来源批次，取消或重新核验 | resolve-conflict |
| 用户与审批组 | 账号状态、角色、组成员、资源管理员 | users、approval-groups、managers |
| 规则配置 | 期限、提前量与配额，生成新版本 | policies |
| 统计与审计 | 日期和管理范围筛选，查看操作记录 | statistics、audit-logs |

通知死信处理第一版由受控的运维流程进行。若增加 Web 重试按钮，必须新增管理 API、权限和审计，不直接让页面连接 RabbitMQ 管理接口。

## 3. 学生 App 页面

| 页面 | 展示与交互 | 状态要点 |
| --- | --- | --- |
| 首页 | 查询入口、AI 入口、待处理申请、候补提醒 | 不把旧缓存当最新可用 |
| 条件查询 | 日期、时间、人数、校区、设备筛选 | 缺字段标明，避免猜时间 |
| 查询结果 | 场地与设备组合、来源模式、检查时间 | AVAILABLE/BUSY/CLOSED/UNKNOWN |
| 资源详情 | 属性、开放与占用日历 | 不展示他人个人信息 |
| 确认申请 | 活动名、说明、人数、完整资源、时间 | 显示整笔申请；提交复查 |
| 我的申请 | 按状态分类与分页 | 查看服务端当前状态 |
| 申请详情 | 资源、暂占期限、审批结果、取消 | allowedActions 与实际权限双重检查 |
| 我的候补 | 组内位置、通知、确认期限、关联申请 | 确认成功后跳转待审批申请 |
| 消息中心 | 已读/未读、对象导航 | 打开时读取当前对象状态 |
| AI 查询 | 多轮追问、条件摘要、方案卡片 | 卡片进入普通确认页，不直接写预约 |
| 个人中心 | 资料、退出、会话错误恢复 | 保护会话凭据 |

移动导航建议：首页、我的申请、消息、个人中心；AI 与候补作为首页和申请页入口，避免把技术组件名称暴露给用户。

## 4. 关键交互

### 查询与提交

选择条件 → 获取结果 → 进入资源组合 → 编辑活动资料 → 查看绝对时间与完整资源 → 确认提交 → 展示待审批状态。

提交过程禁用按钮只是体验优化。创建本次动作的 Idempotency-Key，网络重试复用；收到成功结果前不能显示“预约成功”。RESOURCE_CONFLICT 时保留活动说明，刷新可用组合，由用户确认替换。

待审批页面用服务器期限显示剩余时间，并考虑本地时钟偏差；倒计时结束后重新请求状态。服务器判断结果优先于本地倒计时。

### 候补

有冲突 → 用户确认加入固定资源和时间组 → WAITING → 收到 OFFERED 通知 → 展示期限及全部资源 → 用户确认 → PENDING_APPROVAL。

确认按钮明确显示“确认名额并提交审批”。如果名额过期，重新拉取详情，不直接重试生成新申请。位置为组内位置，可因取消或过期而变化。

### AI

输入需求 → 回答追问 → 核对条件摘要 → 查看方案 → 编辑/确认活动申请。明确显示模型提出的条件及资源查询时间，用户可以改正。模型失败时保留条件并进入普通筛选。

## 5. 前端模块组织

Web：pages、components、api、stores、types、utils、router。App 同样按页面、API、store、DTO 和平台能力隔离；uni-app 的页面路由与生命周期按其机制实现。

请求层统一处理 baseUrl、Authorization、traceId、超时、业务错误、分页、幂等键。访问令牌过期时单次刷新，其余请求排队；刷新失败进入登录，避免循环刷新。

列表缓存按用户/角色/筛选分区；登出和角色变化清理相关状态。所有 ID 使用 string，时间展示采用业务时区。审批/状态操作发送 expectedVersion；冲突后重新加载，不在前端覆盖版本。

类型定义从固定的 API schema 生成或维护，Web 与 App 同步版本。校验用同一套业务边界，但服务端始终重复校验。

## 6. iOS / Android 适配

- 验证安全区、软键盘、不同屏幕、字体缩放、长列表分页和日历触摸。
- 前后台切换后刷新申请与候补状态；进程退出不能保留假的在途成功。
- 服务端地址为设备能访问的 HTTPS 地址；真机中的 localhost 指设备自身。
- 账号凭据采用平台安全存储能力，选择的插件需要两平台验证；不把刷新令牌长期放在普通明文配置里。
- 明确 HBuilderX 打包方式、Android 签名、iOS 签名/设备/模拟器方案。构建成功后分别安装并完成业务流程。
- 系统离线推送需要额外适配服务和平台配置；站内消息可作为第一期实际交付。

## 7. 页面验收

检查空列表、错误字段、长资源名称、未知容量、来源未更新、未登录、无权限、网络中断、重复点击、版本冲突、模型失败和候补过期。按钮状态、弹窗和消息表达必须对应后端实际状态。

页面原型在业务确认后制作，本文不代表原型图或 UI 已完成。
