# M3 联合预约闭环

日期：2026-10-13。承接 [可用性基础](14-M3可用性基础验收.md)，实现一处场地与最多 40 件单件设备的联合申请、暂占、审批、取消、到期释放和来源冲突复核。学校真实资料仍由用户后续提供；本次验收仅使用有独立来源前缀、自动清理的 DEMO 资料，不预置真实预约制度。

## 1. 功能与边界

学生和教师使用已认证账号提交申请；申请人、审批组、资源数据模式与策略版本由后端确定。管理员角色本身不能替代学生或教师资格。教师不会自动取得审批权限：需要另有 RESOURCE_ADMIN 角色并加入对应审批组，或具有 SYSTEM_ADMIN 角色。单独被授予资源维护范围也不等于有权审批。

Web 在可用组合中提供“申请此组合”，保留查询成功时的时间、人数、设施条件和资源成员，再填写活动名称与说明。提交时重新核验数据库；编辑查询条件不会悄悄改变旧方案的申请内容。“我的申请”展示本人记录，“预约审批”展示当前授权组的记录，两页均支持状态筛选、分页、详情及处理历史。服务端 allowedActions 只帮助展示按钮，写入仍核验权限、版本与状态。

| 状态 | 全组占用 | 行为 |
| --- | --- | --- |
| PENDING_APPROVAL | HOLD | 暂占截止取当前时间加审批 TTL 与开始时间减提前量的较早值；必须晚于当前时间 |
| APPROVED | CONFIRMED | 重新核验后批准；结束后自动转 COMPLETED |
| CONFLICT_REVIEW | 保留 CONFIRMED | 明确提示不能视作正常预约；不自动恢复或完成 |
| REJECTED / CANCELLED / EXPIRED / COMPLETED | RELEASED | 整组释放，保留申请、审批记录和审计历史 |

普通取消使用提交时的 cancelLeadMinutes 快照，在活动开始前且未超过截止时间时允许本人或授权管理员操作。审批只能在活动开始前且 HOLD 未过期时完成。驳回必须说明原因。冲突处置由授权管理员提交非空理由：CANCEL 整组释放，包含已开始或已结束的冲突活动；REVALIDATE 仅在开始前允许，重新校验全部资源、当前来源覆盖、开放规则、当前策略最长时长和申请人资格，排除本申请占用后仍需检查其他申请占用。

来源占用新增、修改、停用，时间数据导入，目录元数据修改及开放规则修改，均在原写事务中检查关联申请。失效的待审批申请转 REJECTED 并释放全组，已批准申请转 CONFLICT_REVIEW 保留占用。解除来源冲突不会自动恢复批准。导入确认返回 affectedApplications，其中 rejected 和 conflictReview 为本次状态变化数量；幂等重放返回保存的原批次结果。

来源证据自然过期会使查询变为 UNKNOWN，批准和复核也会拒绝；证据过期本身不批量改写所有已批准申请。策略新版本不追溯重算已有暂占和取消截止；批准/复核读取当前策略检查资源和时长，提交时的完整策略快照仍供历史解释。

## 2. 接口

基础路径 `/api/v1`；所有申请/资源/用户 ID 为字符串，时间携带偏移、最多毫秒精度。申请读写响应均设置 Cache-Control: no-store。写入必须携带 8–64 位 Idempotency-Key。

| 方法 | 路径 | 输入与范围 |
| --- | --- | --- |
| POST | `/applications` | 学生/教师；activityName、description、participantCount、startAt、endAt、venueId、equipmentIds、requiredFeatures |
| GET | `/applications` | 本人列表；status、page、size |
| GET | `/applications/{id}` | 本人或当前授权审批组管理员；他人或越界返回 404 |
| GET | `/admin/applications` | 当前授权审批组；status、page、size；系统管理员可查看全部 |
| POST | `/applications/{id}/cancel` | expectedVersion、可选 reason，检查取消截止 |
| POST | `/admin/applications/{id}/approve` | expectedVersion、可选 reason，重新核验资格与整组资源 |
| POST | `/admin/applications/{id}/reject` | expectedVersion、非空 reason |
| POST | `/admin/applications/{id}/resolve-conflict` | expectedVersion、action=CANCEL/REVALIDATE、非空 reason |

成功提交 HTTP 201，状态为 PENDING_APPROVAL、version=0；状态动作成功 HTTP 200、version 加一。详情包含资源与申请人快照、审批历史和 allowedActions。已提交成员固定，不提供修改组合接口；需求变化应取消后重新查询提交。

关键错误：RESOURCE_CONFLICT / VERSION_CONFLICT / INVALID_STATE / IDEMPOTENCY_KEY_REUSED 为 409；APPLICATION_LIMIT_REACHED / COVERAGE_UNKNOWN / RESOURCE_CLOSED / APPLICANT_INELIGIBLE / CANCELLATION_DEADLINE_PASSED 为 422。申请输入、相同成员重复、未知身份字段、无偏移/跨上海自然日时间等返回 400。到期审批先提交 EXPIRED、释放和历史，再返回 409 APPROVAL_HOLD_EXPIRED；该错误结果也按原幂等键保存，避免返回拒绝后数据库仍保留有效暂占。

日历与可用性查询同时读取外部占用和平台占用；HOLD 仅在 expires_at 大于数据库当前时间时有效，CONFIRMED 按活动区间生效，端点相接不冲突。日历仅暴露 startAt/endAt/type（EXTERNAL、HOLD、CONFIRMED、CONFLICT_REVIEW），不暴露申请人、活动内容、申请 ID 或审批备注。

## 3. 事务与一致性

预约写连接使用 READ COMMITTED，申请列表、详情、查询和日历读取使用 REPEATABLE READ 快照。所有目录与预约写入共用幂等事务，顺序为：幂等行 → 固定 booking_write_guard → 增额时 applicant_guard → 升序资源行 → 申请行。新请求取得协调行后，先扩展被修改资源关联的有效申请全部成员，再统一按主键升序加锁，避免修改一个设备时反向获取整组其他资源造成锁顺序交叉。

首版固定协调行会串行化预约与目录业务写入，用于保证来源批次、关联集合和整组释放的一致性；仍有实际资源行锁及稳定用户配额守卫。本阶段没有做吞吐压测，不据此宣称达到线上容量指标；将来缩小协调范围前必须保留同等并发验收。

申请、明细、全部占用、状态版本、审批记录、审计与 Outbox 同事务成功或回滚。每个申请版本只有一个 Outbox 事件；每个旧状态版本只有一条审批历史。异常发生在后续设备写入时，前序成员和申请也回滚。批准与取消竞争只允许一笔动作使用当前版本；另一笔刷新后由用户重新决定，不自动重试新的审批动作。

资格查询在预约事务开始前调用身份服务，不在持有数据库行锁时等待 HTTP；操作发起人每请求仍实时验真。跨身份库资格读取与预约库提交不是分布式原子事务，不能承诺管理员停用账号与已开始的审批请求之间完全无竞态。后续如需更严格的跨服务撤销语义，应单独设计版本/授权协议。

到期任务先读取最多 100 个候选 ID，逐笔获取相同写锁协议并重读状态；默认启动后 3 秒、每 5 秒扫描。BOOKING_LIFECYCLE_INITIAL_DELAY_MS / BOOKING_LIFECYCLE_DELAY_MS 可调整。过期 HOLD 在任务处理前已不阻挡查询；提交和动作也执行到期检查。多实例重复扫描不重复生成版本或释放；CONFLICT_REVIEW 必须人工处置。

## 4. 迁移与恢复

新增 Flyway V3 建立 booking_write_guard、applicant_guard、activity_application、application_resource、resource_occupancy、approval_record、outbox_event。V1/V2 内容保持原样，V3 已执行后也禁止重新排版或修改。库内关系使用 RESTRICT 外键；状态、区间和版本带 CHECK；资源成员与占用通过复合外键保持一致。用户是跨库逻辑引用并保留快照。

本阶段 resource_occupancy 的 owner 仅支持申请，候补 owner 转移需在 M4 新增迁移。Outbox 已持久化 PENDING 事件，尚未实现 RabbitMQ 认领、发送、确认、消费去重和用户通知，不能将 Outbox 记录解释为已送达消息。

执行 V3 前已将 dev 预约库备份至被忽略的 `deployment/secrets/dev/backups/booking-before-applications-20261013-*.sql`，权限 600。已有业务数据应采用前向修复，或停机并额外备份当前数据后在独立数据库恢复、核对 Flyway 历史再切换。提供 `deployment/mysql/rollback-empty-applications.sql` 供人工审查，仅空 V3 环境可回退；非空申请、占用、事件或用户守卫时拒绝。该脚本本次未执行，MySQL DDL 不能假定整体事务回滚，且本次未完成灾备恢复演练。
