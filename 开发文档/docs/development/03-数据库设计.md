# 数据库设计

## 1. 通用约定

数据库为 MySQL 8.4，表引擎 InnoDB，字符集 utf8mb4。每张业务表含 `id BIGINT PK`、`created_at DATETIME(3)`、`updated_at DATETIME(3)`；下文不重复列出。复合主键关系表明确列出。所有时间保存 UTC，接口转换见工程约定。

N 表示 NOT NULL，? 表示可空。状态使用受校验的 VARCHAR，避免迁移困难的数据库 ENUM。关系数据独立成表，历史记录保留；业务下线通过状态处理，不删除被申请引用的资源。CHECK 校验范围，复杂跨行约束由事务协议保证。

库内外键采用 ON DELETE RESTRICT，防止删除历史关联；跨库用户 ID 通过身份服务校验并保留快照，不建立跨库外键。JSON 只存原始来源、规则快照、模型结果和事件载荷，资源成员关系不用逗号拼接或 JSON 替代。

M2 身份与目录结构已由两服务 Flyway V1 实际建立；后续预约/占用/通知/AI 表仍是设计。具体范围与证据见 [M2 验收](13-M2身份目录验收.md)。

## 2. 身份库 identity_db

| 表 | 业务字段 | 约束与索引 |
| --- | --- | --- |
| `user` | username VARCHAR(64) N；password_hash VARCHAR(100) N；display_name VARCHAR(100) N；status VARCHAR(16) N；auth_version INT N | UNIQUE(username)；status∈ACTIVE/DISABLED；auth_version≥0 |
| `role` | code VARCHAR(32) N；name VARCHAR(64) N | UNIQUE(code)；预置三种角色 |
| `user_role` | user_id BIGINT N；role_id BIGINT N | PK(user_id,role_id)；FK 两列；INDEX(role_id)；无自增 id |
| `user_session` | user_id BIGINT N；device_id VARCHAR(64) N；device_type VARCHAR(16) N；refresh_token_hash CHAR(64) N；previous_token_hash CHAR(64) ?；previous_token_until DATETIME(3) ?；expires_at DATETIME(3) N；revoked_at DATETIME(3) ?；version INT N | FK(user_id)；UNIQUE(refresh_token_hash)；INDEX(user_id,revoked_at)；INDEX(expires_at) |

`used_refresh_token(session_id, token_hash, expires_at)` 保存会话内全部已轮换 hash，避免仅记上一枚令牌无法识别更早重用；`identity_admin_guard(id=1)` 串行保护最后一位有效系统管理员的变更；身份库独立审计表保存操作与 traceId。

会话轮换与并发刷新由服务事务处理，hash 的比较不要将令牌明文写入数据库。身份服务另设本服务 `idempotency_record`，结构同下文通用表。

## 3. 预约库 booking_db：目录与规则

### resource

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| id | BIGINT PK | 平台资源 ID |
| resource_type | VARCHAR(16) N | VENUE / EQUIPMENT |
| source_system | VARCHAR(32) N | 来源系统，平台维护资源也有明确来源代码 |
| source_id | VARCHAR(64) N | 学校场地编号或平台设备编号 |
| name | VARCHAR(200) N | 名称 |
| campus | VARCHAR(100) ? | 校区 |
| building | VARCHAR(100) ? | 楼栋 |
| floor_no | VARCHAR(16) ? | 楼层标签，保留 B1 等可能值 |
| category | VARCHAR(100) ? | 来源类别 |
| subcategory | VARCHAR(100) ? | 二级类别 |
| capacity | INT ? | 场地容量，设备可空；CHECK(capacity≥0) |
| exam_capacity | INT ? | 来源考试容量，不能当活动容量 |
| area | DECIMAL(10,2) ? | 面积，单位 m²；CHECK(area≥0) |
| source_borrowable | VARCHAR(16) N | YES / NO / UNKNOWN |
| platform_status | VARCHAR(16) N | DRAFT / OPEN / CLOSED / RETIRED |
| approval_group_id | BIGINT ? | FK approval_group；开放资源必须绑定 |
| data_mode | VARCHAR(16) N | REAL / DEMO |
| remark | TEXT ? | 原始备注 |
| raw_payload | JSON ? | 原始导入字段，去除无关身份和登录字段 |
| import_batch_id | BIGINT ? | FK import_batch |
| version | INT N | 规则与资料并发修改版本 |

约束：UNIQUE(source_system,source_id,data_mode)；INDEX(platform_status,resource_type,campus)；INDEX(approval_group_id)；INDEX(import_batch_id)。开放资源的完整性在事务校验中检查。来源 NO 在 REAL 模式下不能仅靠管理员点击 OPEN 绕过，需获得确认并记录依据。

## 4. 预约库：来源覆盖与占用

| 表 | 字段 | 约束与索引 |
| --- | --- | --- |
| `import_batch` | source_system VARCHAR(32) N；import_type VARCHAR(32) N；data_mode VARCHAR(16) N；filename VARCHAR(255) N；file_storage_key VARCHAR(500) N；file_sha256 CHAR(64) N；status VARCHAR(24) N；operator_id BIGINT N；field_mapping JSON N；preview_result JSON ?；committed_at DATETIME(3) ?；query_context JSON ? | INDEX(status,created_at)；INDEX(source_system,file_sha256)；状态 PREVIEWED/COMMITTED/FAILED；相同文件不单独判定重复，确认操作另有幂等键 |
| `import_error` | batch_id BIGINT N；row_number INT N；field_name VARCHAR(64) ?；error_code VARCHAR(64) N；message VARCHAR(500) N | FK batch；INDEX(batch_id,row_number) |
| `availability_coverage` | resource_id BIGINT N；source_system VARCHAR(32) N；from_at DATETIME(3) N；to_at DATETIME(3) N；checked_at DATETIME(3) N；completeness VARCHAR(16) N；import_batch_id BIGINT N；data_mode VARCHAR(16) N | FK resource/batch；INDEX(resource_id,from_at,to_at)；COMPLETE/PARTIAL；CHECK(to_at>from_at) |
| `external_occupancy` | resource_id BIGINT N；source_key VARCHAR(128) N；start_at DATETIME(3) N；end_at DATETIME(3) N；reason_code VARCHAR(32) N；source_system VARCHAR(32) N；import_batch_id BIGINT N；active TINYINT N；data_mode VARCHAR(16) N | FK resource/batch；UNIQUE(source_system,source_key,resource_id,data_mode)；INDEX(resource_id,active,start_at,end_at)；CHECK(end_at>start_at) |

空闲结果导入只能给“经确认的某资源某区间”建立覆盖证据；学校完整占用表导入才可在明确范围内处理缺失条目。单次文件中没有的记录不默认删除。基础目录导入不创建覆盖证明。

## 5. 预约库：申请、审批与候补

### activity_application

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| applicant_id | BIGINT N | 身份服务用户 ID |
| activity_name | VARCHAR(200) N | 活动名称 |
| description | TEXT ? | 活动说明 |
| participant_count | INT N | CHECK > 0 |
| start_at / end_at | DATETIME(3) N | 活动区间，CHECK(end_at>start_at) |
| status | VARCHAR(32) N | 状态见流程文档 |
| approval_group_id | BIGINT N | FK approval_group |
| hold_expires_at | DATETIME(3) ? | 待审批暂占到期，批准后为空 |
| policy_version | INT N | 使用的策略版本 |
| policy_snapshot | JSON N | 当时关键规则 |
| applicant_snapshot | JSON N | 最小必要显示快照，避免跨库实时 JOIN |
| data_mode | VARCHAR(16) N | REAL / DEMO |
| last_reason | VARCHAR(500) ? | 最后状态变化原因 |
| version | INT N | 乐观状态版本 |

索引：INDEX(applicant_id,status,created_at)、INDEX(approval_group_id,status,created_at)、INDEX(status,hold_expires_at)。所有申请包含一处场地，资源成员创建后不可修改；修改需求采用取消后新申请。

| 表 | 字段 | 约束与索引 |
| --- | --- | --- |
| `application_resource` | application_id BIGINT N；resource_id BIGINT N；resource_snapshot JSON N | PK(application_id,resource_id)；FK 两列；INDEX(resource_id,application_id) |
| `approval_record` | application_id BIGINT N；operator_id BIGINT N；decision VARCHAR(32) N；reason VARCHAR(500) ?；from_version INT N | FK application；INDEX(application_id,created_at)；INDEX(operator_id) |
| `waitlist_group` | group_key CHAR(64) N；start_at DATETIME(3) N；end_at DATETIME(3) N；data_mode VARCHAR(16) N；version INT N | UNIQUE(group_key)；CHECK(end_at>start_at)；group_key 对应排序后的资源集合与固定区间 |
| `waitlist_entry` | group_id BIGINT N；applicant_id BIGINT N；activity_name VARCHAR(200) N；description TEXT ?；participant_count INT N；status VARCHAR(24) N；offer_expires_at DATETIME(3) ?；application_id BIGINT ?；policy_snapshot JSON N；version INT N | FK group/application；INDEX(group_id,status,created_at,id)；INDEX(applicant_id,status)；INDEX(status,offer_expires_at) |
| `waitlist_group_resource` | group_id BIGINT N；resource_id BIGINT N | PK(group_id,resource_id)；FK 两列；INDEX(resource_id,group_id)；同组成员共享固定资源集合 |

group_key 使用规范化的资源 ID、UTC 起止时间和 data_mode 计算 hash；资源集合由 waitlist_group_resource 保存，时间与模式由 group 保存，在读取时核对，不能只信 hash。申请人同组同时有效候补唯一性通过锁定 group 行后校验。

### resource_occupancy

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| resource_id | BIGINT N | FK resource |
| application_id | BIGINT ? | FK activity_application |
| waitlist_entry_id | BIGINT ? | FK waitlist_entry |
| start_at / end_at | DATETIME(3) N | 区间 |
| status | VARCHAR(16) N | HOLD / CONFIRMED / RELEASED |
| expires_at | DATETIME(3) ? | HOLD 必须有，CONFIRMED 无 |
| released_at | DATETIME(3) ? | 释放时间 |

CHECK：end_at>start_at；application_id 与 waitlist_entry_id 恰好一个非空；HOLD 必须有 expires_at。索引：INDEX(resource_id,status,start_at,end_at)、INDEX(application_id)、INDEX(waitlist_entry_id)、INDEX(status,expires_at)。

时间重叠不能用普通 UNIQUE 索引保证。统一资源行锁协议是必需约束；后台、导入、候补和定时任务都必须遵守。

## 6. 预约库：幂等、事件与审计

| 表 | 字段 | 约束与索引 |
| --- | --- | --- |
| `applicant_guard` | user_id BIGINT N | PK(user_id)，替代通用 id；有 created_at/updated_at；用于串行检查增加配额的操作 |
| `idempotency_record` | actor_id BIGINT N；operation VARCHAR(64) N；request_key VARCHAR(64) N；payload_hash CHAR(64) N；status VARCHAR(16) N；http_status INT ?；response_body JSON ?；expires_at DATETIME(3) N | UNIQUE(actor_id,operation,request_key)；INDEX(expires_at)；IN_PROGRESS/SUCCEEDED |
| `outbox_event` | event_id CHAR(36) N；event_type VARCHAR(64) N；aggregate_type VARCHAR(32) N；aggregate_id BIGINT N；aggregate_version INT N；payload JSON N；status VARCHAR(16) N；attempts INT N；next_attempt_at DATETIME(3) N；claim_token CHAR(36) ?；claim_expires_at DATETIME(3) ?；published_at DATETIME(3) ? | UNIQUE(event_id)；INDEX(status,next_attempt_at)；INDEX(claim_expires_at)；PENDING/SENDING/SENT/FAILED |
| `audit_log` | actor_id BIGINT ?；action VARCHAR(64) N；object_type VARCHAR(32) N；object_id BIGINT N；from_status VARCHAR(32) ?；to_status VARCHAR(32) ?；reason VARCHAR(500) ?；trace_id VARCHAR(64) N | INDEX(object_type,object_id,created_at)；INDEX(actor_id,created_at) |

幂等成功记录与业务同事务提交；失败事务回滚时不会留下成功记录。身份、通知与 AI 服务按各自写接口需要使用同结构的幂等表，不能共享预约库。身份服务使用同结构本地 audit_log 记录账号和角色变更。自然幂等的已读动作和有 clientMessageId 的消息也要保持响应一致。外部服务调用不放在预约事务中等待。

## 10. 查询与迁移

关键查询先按 resource_id 和有效状态筛选，再做区间判断；外部占用与覆盖单独核对。目录分页不读取全部 raw_payload。使用 EXPLAIN 检查核心查询，索引数量按实际访问模式调整。

Flyway 建议按 identity → booking 目录 → 申请候补 → 占用事件 → 通知 → AI 的依赖组织各库版本。先建父表，再建外键和子表。生产式环境变更前备份并验证恢复；MySQL DDL 有隐式提交行为，不能假定 BEGIN/ROLLBACK 能撤销所有建表或改表操作。回退采用经过验证的反向迁移或备份恢复，不能只依赖 ORM 自动建表。

本文件为字段设计，未生成或执行 SQL。实施时由字段字典生成迁移，再在真实 MySQL 上检查约束、索引和事务行为。
