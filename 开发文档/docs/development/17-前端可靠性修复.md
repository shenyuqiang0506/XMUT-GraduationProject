# 前端可靠性修复

日期：2026-10-13。范围：已核实的分页重试、上海时区输入、JSON 校验、请求错误及会话刷新问题，未增加预约业务。

## 分页加载

可用性查询、资料导入和开放占用管理使用共同的 `usePagedOptions` 加载资源选项：

- 请求中立即设置独立 loading 状态，事件处理层拒绝重复加载，按钮同时禁用。
- 请求成功才推进页码；失败重试仍请求原页，不跳过资料。
- 按资源 ID 合并相邻页，重复 ID 更新内容，不产生重复选项。
- 根据服务端分页范围判断结束，不因去重后的条数少于 total 而无限加载空页。

目录发生持续变化时，按偏移量分页仍不能保证完整快照；需要用户重新进入页面刷新目录。服务端权限检查保持有效。

## 上海时区输入

查询起止时间、时间资料导入和外部占用统一使用 `ShanghaiDateTime`。控件保留墙上时刻字符串，转换时明确追加 `+08:00`，不随浏览器时区转换。

验证发现：仅给原日期控件设置字符串 value-format，仍会受到浏览器夏令时影响，例如洛杉矶切换日输入 02:30 被改为 03:30。因此使用 Element Plus 外观的原生 datetime-local 输入，保存不带时区的日期和时刻，集中转换与校验。显示格式随浏览器语言设置，输入含义始终为页面标明的上海时间。

组合查询在发送前检查日期有效性、区间顺序及同一上海自然日；日历、占用和来源覆盖保留跨日区间能力，由后端继续检查各自最大范围。开放规则的纯日期与本地时刻输入保持原契约。

## JSON 与请求错误

设施配置、字段映射、来源说明提供中文 JSON 提示。数组、null 和基本值不能作为对象使用；设施和字段映射的值必须为字符串。后端仍负责字段白名单、格式、权限及业务最终校验。

请求传输与响应解析集中在不依赖会话的 `api/http.ts`，登录、刷新、当前身份和业务请求共用：

- HTML、空响应、无效响应信封转为中文 `ApiError`，保留 HTTP 状态与可用追踪号。
- 超时、断网采用不同错误码，不直接展示浏览器英文异常。
- 刷新服务的 503 保留为服务故障，不伪装成登录过期。
- `/users/me` 补充客户端追踪号；业务请求遇到 401 仍仅刷新和重试一次。

## 会话与幂等

会话代数在退出、清理或重新登录时递增，正常令牌轮换不改变代数。旧登录或刷新响应晚到时，不接受旧令牌或旧身份；旧业务请求不能使用另一个账号的新令牌重试。并发 401 仍共用一次刷新任务。

退出时先清理本地状态，再尽力撤销服务端会话；网络失败不阻止本地退出。身份服务会话校验与撤销仍为服务端依据。

幂等键在结果未知时保留：断网、超时、无效响应均不能证明服务器未写入，不能在 catch/finally 里无条件删除键。明确成功后才释放原键。操作范围与内容使用明确结构计算前端指纹，避免直接拼接产生边界碰撞。

cd web-admin
