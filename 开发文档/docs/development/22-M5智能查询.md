# M5 智能资源查询

日期：2026-10-14。实现 Java/Spring AI 条件提取、本人会话、受控只读工具与 Web 查询/确认页面。模型不创建、审批、取消申请，也不改写占用。

## 1. 用户流程

学生或教师在 Web“智能资源查询”新建 REAL 会话，描述需求，回答追问，核对条件及方案后填写活动信息并确认。卡片包含真实资源名称、配套设备、上海时刻、人数、规则版本/依据与核查时间。确认调用原 /applications；提交前资源被占用会返回冲突并保留活动表单。AI 查询不表示预约成功，提交后仍需审批。

纯管理角色没有此入口，后台也拒绝 AI 会话接口。管理角色与学生/教师角色可另行组合授权。REAL 制度、目录或覆盖资料缺失时不生成虚构方案。页面只新建 REAL 会话；自动验收显式使用隔离 DEMO，不把测试记录当成真实资料。

## 2. 条件与模型边界

一次提取只返回 changes/evidence，允许字段：campus、date、startLocal、endLocal、durationMinutes、participantCount、requiredFeatures、equipmentRequirements、preferredBuilding。每个增量必须引用当前用户原文，不改写未明确变更的旧条件。人数、日期、时刻、时长由服务器再次解析原文，模型猜测值不作为查询条件。

支持带年份 ISO/中文日期、今天/明天/后天、本周/下周星期、HH:mm、中文明确几点/几点半、整数小时或分钟，以及“两个半小时”等复合时长。“下午3:00”和“下午三点”均解析为 15:00，两个半小时为 150 分钟；矛盾时段或多个时刻要求补充。“下午”“晚上”、小数时刻、负数、人数范围或估计人数需要补充；已经过去的周内日期不自动挪到下周。“人数改成八”保留其他条件；设备类型须使用当前可见目录原值，数量需明确。跨上海自然日、缺人数/时刻或未知目录选项都会阻止查询。

复审后提取提示版本为 conditions-v2。设施、设备增量用 `{operation,items}` 表达：MERGE 保留其他项并设定指定设备数量，ADD 明确追加并累加同类设备数量，REMOVE 删除指定项，REPLACE 仅用于“只要/全部换成”等整体替换，CLEAR 仅用于明确取消全部要求。操作与修改项都须有当前消息证据；服务器保存的条件仍是普通数组，前端及业务查询契约不变。旧版数组按证据推断增量操作，不再默认整体覆盖；局部取消的空数组仅删除证据中提到的项。合并后的数量、类型数及总量继续校验，超限要求澄清。

“不用再加网络”等否定追加，以及不能用单次操作表达的混合追加/取消，不能充当追加或删除证据；模型错误标注操作时服务器拒绝本次修改并保留旧条件。

模型请求只包含有限历史（最多四条）、当前条件、可见选项与服务器上海日期，不携带用户令牌、服务密钥或他人申请。响应限制 8,000 字符，拒绝围栏、附加 JSON 根、额外字段、虚构资源 ID 和截断输出；内部推理不保存。使用 JSON Object 输出、关闭思考，没有注册模型写工具，参考 [DeepSeek JSON 输出](https://api-docs.deepseek.com/guides/json_mode/) 和 [Spring AI OpenAI 适配](https://docs.spring.io/spring-ai/reference/api/chat/openai-chat.html)。

## 3. 只读工具与授权

由 Java 编排固定调用，模型不能自由指定 URL 或 SQL：

| 工具 | 业务接口 | 边界 |
| --- | --- | --- |
| getVisibleOptions | GET /resources/options?dataMode=... | 当前可见校区、设备类型，每类最多 200 项 |
| getBookingRules | GET /booking-rules?dataMode=... | 当前模式生效规则，只有读取权限 |
| searchAvailableResources | POST /availability/search | 复用覆盖、开放、人数、设施、设备及审批组判断，最多三套方案 |
| getResourceDetails | POST /resources/details | 只读查询结果中的 ID，最多 128 项，每项复用详情授权 |

请求中的可信用户令牌直接交给预约服务实时复核。返回回答前再次确认身份，模型等待期间停用账号会拒绝响应。方案 ID 来自工具结果，并检查成员、模式、覆盖、审批组和规则版本；规则读取与搜索之间版本变化时返回 RULES_CHANGED，不混用旧依据。历史方案及幂等回放也按当前权限复核，资源被隐藏时清除方案；旧对话摘要不包含旧方案详情。

NO_MATCH 只汇总可见候选原因：TIME_OCCUPIED、OUTSIDE_OPENING_OR_CLOSED、COVERAGE_UNKNOWN、EQUIPMENT_UNAVAILABLE_OR_INSUFFICIENT、NO_MATCHING_CATALOG。不返回隐藏资源或他人活动，不用 UNKNOWN 推断空闲。时间不符合提前量、最远日期或最大时长时提示修改。

## 4. 状态、去重与恢复

独立 ai_db 使用 ai_conversation、ai_message、ai_tool_call、ai_user_budget。owner_id 是跨服务用户标识，不建跨库外键；消息/工具轨迹使用本库外键，创建键和消息键按 ascii_bin 比较，状态、版本、处理中结果及租约有 CHECK 约束。

认领锁顺序为用户预算行→本人会话行。认领/提交都是最长三秒的短事务，模型和 HTTP 不在事务内等待。每会话只允许一条在途消息；其他新消息返回 AI_CONVERSATION_BUSY，同消息在途返回 AI_MESSAGE_PROCESSING。已完成重复消息核对原文本及 expectedConditionVersion 后回放；内容不同返回 AI_MESSAGE_ID_REUSED，不重复执行模型。新消息须匹配当前条件版本，处理结束增加版本。

租约 20 秒，总工作预算 10 秒，最多八个并行任务。模型客户端与 chat 请求默认 6 秒、零自动重试；须单独设置 chat timeout，避免其默认值覆盖根配置。Web 消息请求每次最多 20 秒，留出实时认证与短事务余量；未知网络结果保留原消息编号/版本，通过读取或原消息重试恢复。

条件验证后保存检查点。模型/工具失败、总预算超时或过期租约仍保留已经校验的意图。旧任务不能覆盖新租约或完成结果。过期租约在本人读取/发送请求时标记 FAILED 并释放，不重放可能已经收费的调用。恢复验收使用模拟的已提交中断状态，没有宣称完成所有网络、多节点故障演练。

默认每用户在一小时计数窗口内最多受理 20 条新消息（AI_HOURLY_LIMIT，跨会话共用）；窗口自预算行建立起计时，到期后的下一次受理重置计数，不是滑动窗口。每人最多 20 个 ACTIVE 会话，每会话最多 40 条消息。关闭后可新建，历史仍归本人。重复回放不增加预算。这些值是技术保护，不是学校制度或模型准确率承诺。

## 5. API 与前端

| 方法 | 路径 | 权限与主要参数 |
| --- | --- | --- |
| POST | /ai/conversations | S/T；dataMode、Idempotency-Key；201 返回 conversationId、version、conditions |
| GET | /ai/conversations | S/T；本人最近 20 个 ACTIVE 会话 |
| POST | /ai/conversations/{id}/messages | S/T 且归本人；text≤2,000 字符、clientMessageId、expectedConditionVersion |
| GET | /ai/conversations/{id}/messages | 本人最近十条摘要、会话状态及当前权限复核后的最新方案 |
| POST | /ai/conversations/{id}/close | 本人；expectedConditionVersion；处理中需等待，关闭后拒绝新消息 |

结果为 NEED_CLARIFICATION / READY / NO_MATCH / FAILED；读取中可为 PROCESSING。结果含 messageId、conditionVersion、conditions、missingFields、reply、plans、checkedAt；失败有 errorCode，无匹配有 reasonCodes。响应 no-store；创建及消息回放带 Idempotency-Replayed。

前端以会话/请求编号保护迟到响应。未知网络结果冻结原发送内容，允许读结果或重试；版本冲突则读取最新条件。未配置模型、规则缺失或服务故障给出中文提示。“改用普通查询”携带已确认条件，保留上海时间和人数，不自动查询/提交。普通申请确认采用稳定幂等键，冲突时保留活动名称与说明。

创建成功即切换当前会话及消息目标，辅助列表失败不恢复旧会话；发送前核对选择与目标一致。同一会话刷新失败保留已确认条件与历史文字，清除需要重新核查的旧方案；发送成功后先保存响应中的条件及版本，再读取历史，后续读取失败也能继续发送或降级查询。AI 确认表活动说明最多 2,000 字符，输入限制和提交前校验与普通申请后端一致。

## 6. 环境、迁移与启动

~~~sh
python3 deployment/scripts/prepare-ai.py dev
python3 deployment/scripts/prepare-ai.py prod
python3 deployment/scripts/prepare-idea.py
./GraduationProject/mvnw -s .mvn/settings.xml -B -ntp package
~~~

私密 secrets/dev/ai.env 仅交给 AI 服务，使用既有独立 ai_dev 数据库账号；dev 可沿用被忽略的 deployment/.env.ai DeepSeek 配置。文件权限 600，不覆盖已有配置。prod 使用 ai_prod，默认 AI_PROVIDER=disabled，不继承 dev 模型密钥，未启动 prod。身份私钥、后台资格密钥、登录来源密钥不交给 AI。

IDEA“后端总启动（dev）”包含身份 8083、预约 8082、通知 8085、智能查询 8084、网关 8081，Web 为 5173。新增“智能查询服务（dev）”。同步新增 Maven 依赖后使用总启动；dev-workspace.py 同样支持五个 Java 服务与 Web。

AI V1 已在 dev 执行，**不得修改或重新排版**，后续结构新增 V2。空 AI 库此前备份到被忽略的 deployment/secrets/dev/backups/before-ai-20261014.sql，权限 600。恢复先停止 AI 写入，将备份恢复到独立数据库并核对，不直接删除现有会话；完整恢复演练仍属后续阶段。预约 V1–V4、身份已有迁移及通知 V1 未修改。

本地模型覆盖追问、增量条件、注入/非法输出、模型超时/失败、去重、额度、在途并发、租约恢复、权限变更与普通提交复核。DeepSeek 两条小样本通过同一正式链路，记录原问题、人工期望、实际条件、方案数量、失败码及耗时；不报告未经系统评估的准确率。浏览器覆盖方案确认、冲突保留表单、消息断网、角色导航和海外时区降级。

启用 XMUT_WEB_TEST 时另运行真实 API 浏览器流程，仅对指定读取请求注入 503；验证会话目标、条件恢复和 2,000 字符普通申请提交/取消。链路同时用 dev 凭据启动未启用 dev/test 的临时预约进程，走禁止 DEMO 的正式分支，检查申请、候补和管理列表的总数/分页及详情权限；不会启动 prod。临时账号、候补、申请、幂等记录与进程均在 finally 清理。
