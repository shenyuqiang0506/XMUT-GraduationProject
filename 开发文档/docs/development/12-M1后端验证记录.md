## 实现与调用链

根 POM 集中版本管理，聚合 common-contracts、service-support、identity-service、GraduationProject（booking-service）、ai-service、gateway。前两个为共享库，后四个独立启动，默认端口依次为 8083、8082、8084、8081。完整业务表、登录和预约 API 尚未实现。

1. HTTP GET `/api/v1/m1/booking/status` → Gateway lb://booking-service → Feign identity-service → 返回统一 JSON。
2. HTTP POST `/api/v1/m1/ai/query`，请求体 `{"text":"查询 demo-venue-1"}` → Spring AI → 模型工具请求 → getResourceDetails → Feign booking-service → 返回工具数据 → 模型生成最终文本。
3. 所有入口校验 X-Trace-Id（8–64 位字母、数字、下划线、短横线），不合法时生成 UUID；服务通过 MDC 和 Feign 传递，响应体及响应头保持一致。

工具仅能读取 demo-venue-1，返回名称“技术验证演示场地”、容量 20、dataMode=DEMO、availability=UNKNOWN。返回 resources 来自工具实际查到的结构化结果，不由模型构造；不会写数据库或创建预约。模型回复属于演示输出，不等于业务条件过滤和权限验收。

## 异常和边界验证

未认证、错误密码、绕过网关直连均返回带 traceId 的 401。非法 traceId 被替换并持续传递；未知资源返回 404，空 AI 文本返回 400。停止验证器自己的 identity 进程后，booking 依赖错误返回 503。

模拟模型 HTTP 503、超时、未调用工具、非法资源参数和持续要求重复工具，均返回 AI_UNAVAILABLE/503。工具单次请求上限 2；第三次工具请求被拒绝，模型/工具不会无限循环。模型 SDK 重试关闭；默认单次模型 HTTP 请求超时 15 秒，模拟模式设置为 1 秒并发送 2 秒慢响应验证超时。

本次修正了 BCrypt 缺少编码前缀的问题；同时按 Spring AI 2.0.1 源码将连接超时显式带入 ChatClient 的默认请求选项，并检查模型 finishReason，防止工具上限错误文本被当作成功回复。只接受正常 stop 结束状态；截断、未完成工具调用不返回成功。

## 复现与凭据

在仓库根目录依次执行：

```sh
./GraduationProject/mvnw -s .mvn/settings.xml -B -ntp verify
python3 deployment/scripts/bootstrap-nacos.py dev
python3 deployment/scripts/init-m1.py
deployment/scripts/verify-dev.sh
python3 deployment/scripts/m1-smoke.py
python3 deployment/scripts/m1-smoke.py --real-model
```

真实模式读取本机 `deployment/.env.ai`，包含 AI_BASE_URL、AI_MODEL、AI_API_KEY；文件权限 600，Git 忽略。开发 Basic 凭据存于 `deployment/secrets/dev/m1.env`，与模型 key 和 Nacos 密码分开。工具、服务之间的开发机器凭据不等同于正式用户身份，生产拒绝 m1 profile。

每次调用链使用独立 Nacos discovery group，避免混入已有实例。验证器在端口占用时退出，完成后停止自己创建的四个 Java 进程；Docker dev 保持运行。先完成构建再启动验证，避免替换运行中的 JAR。私密日志保存在 `deployment/secrets/dev/m1-stub-logs/`、`m1-real-logs/`，不公开、不提交。
