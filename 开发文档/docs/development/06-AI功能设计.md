# AI 功能设计

## 1. 目标

学生自然描述人数、时间、设备和地点偏好，系统转换为可验证条件并查询可行组合。AI 不直接创建、审批、取消或改写占用；方案确认走普通预约接口。

开发采用 Java + Spring AI，选择支持工具调用的模型服务。先验证接口适配、结构化输出、超时与工具调用，再固定模型和参数。无需把 Python 作为本功能必需服务。

## 2. 条件模型

| 字段 | 类型 | 校验 |
| --- | --- | --- |
| campus | string/null | 目录中的已知值，否则追问 |
| startAt / endAt | 带偏移时间/null | 服务端解析相对时间，符合预约窗口 |
| participantCount | integer/null | 正数；缺失不随意补值 |
| requiredFeatures | string[] | 平台特征白名单 |
| equipmentRequirements | {type,count}[] | 类型白名单，count 正数 |
| preferredBuilding | string/null | 偏好，不等同必需条件 |
| explanation | string | 对用户说明当前理解 |

用户说“周五下午”“晚上”“两小时”但缺开始时间时，必须追问。显示绝对日期、起止时间、人数与设备数量，防止用户和服务端对相对日期理解不同。

多轮更新只修改用户明确变更的字段；“人数变成八人”保留时间和设备，“换一间”只更换查询方案，不擅自改时间。需要修改条件才能满足时先提出可选修改，由用户确认。

## 3. 只读工具契约

| 工具 | 输入 | 输出 |
| --- | --- | --- |
| searchAvailableResources | 经过校验的条件 | 同一审批组可行组合、覆盖状态、checkedAt |
| getResourceDetails | 允许访问的 resourceId | 容量、地点、特征、开放状态 |
| getBookingRules | 当前用户与审批组 | 生效规则版本、提前量、取消与候补说明 |

工具运行时从会话请求取得可信用户身份，调用预约服务校验；模型输出不能指定 actorId 或管理员角色。工具使用参数白名单和 DTO 校验，不接受任意 SQL、URL 或执行代码。

工具响应无权限对象不返回，空闲查询不包含他人活动说明。覆盖 UNKNOWN 时明确说明无法确认；模型不能将 UNKNOWN 改成 AVAILABLE。相关机制参考 [Spring AI 工具调用](https://docs.spring.io/spring-ai/reference/api/tools.html)。

## 4. 处理流程

1. 验证会话归属、clientMessageId 和 conditionVersion。
2. 取必要对话上下文与当前条件，限制历史长度和调用预算。
3. 提取新增/修改条件，进行结构和业务校验。
4. 条件不足返回 NEED_CLARIFICATION；不自动调用写工具。
5. 调用只读查询，记录工具参数与业务返回的 traceId。
6. 用真实返回结果构建方案卡片，说明满足与未满足条件。
7. 返回 READY、NO_MATCH 或 FAILED；前端显示可编辑确认页。
8. 用户提交时调用 `/applications`，重新检查所有资源。

同一会话第一版每次只处理一条在途消息；并发更新收到版本冲突并刷新会话。clientMessageId 重复返回既有消息，不重复扣除调用预算。

## 5. 结果输出

READY 结果含条件、候选 resourceIds、名称、时间、设备、审批组、dataMode、checkedAt 和查询依据。后端校验所有资源 ID 来自工具结果，不接受模型虚构 ID。

没有匹配时展示原因类别：时间占用、容量不够、设备不足、不同审批组、覆盖未知。不能把不可见资源的完整信息作为“推荐解释”。

普通筛选是可用的基础入口；模型或网络失败时返回可恢复状态，保留用户已确认条件。

## 6. 约束和配置

模型凭据在服务端配置；对单用户设置调用次数、文本长度、工具轮数和超时上限。提示词和模型名称版本化，记录每次使用版本。工具的实际结果优先于模型文字，输出需结构与业务双重校验。[结构化输出说明](https://docs.spring.io/spring-ai/reference/api/structured-output/converters.html)

规则问答如果后续加入 RAG，需要维护规则来源、有效日期和权限过滤；空闲状态不通过过期规则文档回答。RAG 不属于第一版必需功能。

## 7. 验证范围

| 情况 | 期望 |
| --- | --- |
| 明确时间、人数、设备 | 条件准确且能复核 |
| 缺少开始时间 | 追问，不自行猜测 |
| 多轮修改人数或日期 | 修改指定字段，保留其他条件 |
| 无效设备名、资源 ID | 校验或追问，不生成假方案 |
| 覆盖未知 | 明确 UNKNOWN |
| 请求查看别人申请 | 工具权限拒绝 |
| 查询后资源被别人占用 | 普通提交返回冲突 |
| 模型超时、格式不合法 | 有错误状态和普通查询入口 |

数据样例由开发者亲自整理，验证记录原问题、人工期望、模型条件、工具结果、失败原因与耗时。不预先承诺准确率，不使用模型自评作为唯一评价。
