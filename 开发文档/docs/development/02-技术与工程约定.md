# 技术与工程约定

## 1. 技术基线

沿用 [技术方案](../../技术栈与开发流程.md) 中的完整组件。建议版本线为 Java 21、Boot 4.0.x、Cloud 2025.1.x、Alibaba 2025.1.x、Spring AI 2.0.x、MyBatis-Plus Boot 4 starter、MySQL 8.4/InnoDB、RabbitMQ 4.x、Nacos 3.x。具体补丁版本和 Redis/Nginx/前端依赖在最小集成验证后锁定。

官方适配参考：[Cloud](https://spring.io/projects/spring-cloud/)、[Alibaba](https://sca.aliyun.com/docs/2025.x/overview/version-explain/)、[Spring AI](https://docs.spring.io/spring-ai/reference/getting-started.html)、[MyBatis-Plus](https://baomidou.com/getting-started/install/)。这些对应关系不证明尚未创建的项目能够直接构建。

Web：Vue 3 + TypeScript + Vite + Element Plus + Pinia + Router。App：uni-app Vue 3 + TypeScript + uni-ui；打包环境按 [uni-app 官方说明](https://uniapp.dcloud.net.cn/tutorial/app-base.html) 验证。

## 2. 服务职责

| 服务 | 外部路径 | 数据库 | 写入职责 |
| --- | --- | --- | --- |
| gateway | `/api/v1/**` | 无 | 路由、认证预检查、限流、traceId |
| identity-service | `/auth/**`、`/users/**` | `identity_db` | 用户、角色、会话 |
| booking-service | `/resources/**`、`/availability/**`、`/applications/**`、`/waitlists/**`、`/admin/**` | `booking_db` | 资源、占用、审批、候补、Outbox |
| ai-service | `/ai/**` | `ai_db` | 对话、消息、工具调用记录 |
| notification-service | `/notifications/**` | `notification_db` | 站内消息、消费去重、投递记录 |

管理员账号管理路径仍由 identity 处理；按路由明细配置网关，不使用笼统的 `/admin/**` 覆盖所有服务。

独立数据库账号仅允许操作所属库，同一 MySQL 实例可承载四个逻辑库。库内关系使用外键，跨服务用户 ID 采用逻辑引用和 API 校验。服务通过 API、事件协调，禁止跨库 JOIN 形成隐式耦合。

预约核心使用 Spring MVC 和 JDBC；网关选择 Gateway 的独立运行模型，不在网关中运行预约 SQL。Nacos 配置采用 `spring.config.import`。

## 3. 时间和 ID

- 客户端提交带偏移的 ISO 8601 时间，例如 `2027-03-10T14:00:00+08:00`；不接受没有时区的时间字符串。
- Java 使用 Instant/OffsetDateTime。业务规则按 Asia/Shanghai 转换，数据库 DATETIME(3) 统一保存 UTC 值，数据库连接会话时区为 UTC。
- API 输出时间统一带 `+08:00`，日志可用 UTC，但要包含偏移。定时器使用数据库当前时间判断有效期，测试通过可控时钟推进。
- 区间为 `[startAt,endAt)`，要求 startAt < endAt。同一时刻结束与开始不算重叠。
- 自增 BIGINT 为内部主键；JSON 中所有 ID 输出为字符串，避免 JavaScript 精度问题。
- 学校来源 ID 使用 VARCHAR(64)，不要转为自增主键或与平台 ID 混用。

## 4. HTTP 契约

基础路径 `/api/v1`。普通响应：

```json
{"code":"OK","message":"成功","data":{},"traceId":"示例请求标识"}
```

分页使用 page（从 1 起）、size（默认 20，上限 100），返回 items、page、size、total。筛选和排序字段采用白名单。不得把源系统 totalResult=1132 当作本次导入条数。

错误状态采用 400 参数、401 身份、403 权限、404 不存在或不可见、409 冲突、422 业务不允许、429 限流、503 外部服务暂不可用。业务错误码见接口文档。资源是否存在的返回策略不得泄露无权访问对象。

POST/PATCH 的预约、审批、取消、候补、导入确认等写操作携带 `Idempotency-Key`。每个服务各自管理幂等记录；键绑定用户、动作和规范化请求体 hash。网络重试复用原键，用户发起新动作才换键。

## 5. 身份、权限和会话

JWT 包含 sub、sid、iss、aud、iat、exp；采用固定白名单签名算法。角色可作为提示字段，但角色和资源管理范围以服务端有效授权为准。每个业务服务验证签名、发行者、受众、期限和会话状态。

访问令牌短期有效，刷新令牌使用随机值并只保存 hash。按设备区分会话，刷新采用轮换；重复使用已轮换的刷新令牌需返回明确错误。Web/App 单次刷新串行处理，避免并发刷新导致正常会话被误判。

用户停用和登出记录在 MySQL，并同步会话撤销状态到 Redis；未知或缓存故障时查询身份服务，不能默认有效。管理范围由预约服务查 `approval_group_member` / `resource_manager`。AI 工具沿用当前调用者权限，服务间机器身份不等于用户管理权限。

```text

  common-contracts/
  gateway/
  identity-service/
  booking-service/
  ai-service/
  notification-service/
web-admin/

```

当前 M1 工程直接聚合在根目录，`GraduationProject/` 保留为 booking-service，新增 identity-service、ai-service、common-contracts 和 service-support；notification-service 随通知阶段实现。上述目录图是目标结构。

业务服务内按 controller、application（用例）、domain（规则）、infrastructure（Mapper/外部调用）组织。先固定业务约束再编写接口。公共模块只放稳定契约、错误码和必要公共类型，不共享 Mapper、业务实体与数据库账号。

提交源码、数据库迁移、前端锁文件、示例配置、部署文档和测试说明。配置中的凭据使用环境变量；日志不要输出密码、令牌和模型密钥。模型调用与耗时服务配置超时、次数与并发上限。

## 7. 日志与服务健康

所有入口创建/校验 traceId，并跨 Feign 与消息传递。业务日志包含 actorId、资源/申请 ID、操作、结果、耗时；审计记录另外持久化。AI 日志记录工具名、输入条件和结果来源标识，按权限展示。

Actuator 区分进程存活与依赖就绪，管理端点限制访问。Nacos 注册成功不等于数据库和消息可用。预约在消息暂不可用时仍可通过 Outbox 持久化事件；AI 暂不可用时保留普通查询。
